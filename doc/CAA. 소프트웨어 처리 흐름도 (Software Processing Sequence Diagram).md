처리 흐름도(Sequence Diagram)은 UML(Unified Modeling Language)의 일부로, 객체 간의 상호작용을 시간 순서에 따라 표현하는 다이어그램입니다. 처리 흐름도는 특히 시스템의 동작을 이해하고, 시스템 내에서 메시지가 어떻게 흐르는지를 시각화하는 데 유용합니다.

처리 흐름도의 주요 구성 요소는 다음과 같습니다:

1. 객체(Object): 다이어그램 상단에 수평으로 배치되며, 처리를 담당하는 객체를 의미합니다.

2. 생명선(Lifeline): 각 객체 아래로 길게 뻗어 내려가는 수직선으로, 객체의 생명주기를 나타냅니다. 객체가 시스템 내에서 활동하는 기간 동안 생명선이 계속됩니다.

3. 활성화 바(Activation Bar): 객체가 작업을 수행하고 있음을 나타내는 두꺼운 수직선으로, 생명선 위에 그려집니다. 활성화 바의 길이는 해당 작업의 지속 시간을 나타냅니다.

4. 메시지(Message): 객체 간의 상호작용을 나타내는 화살표로, 메시지를 보내는 객체에서 받는 객체로 향합니다. 메시지는 동기(synchronous), 비동기(asynchronous), 반환(return) 등의 유형이 있으며, 화살표의 스타일과 방향으로 구분됩니다.

5. 생성(Create) 및 파괴(Destroy): 객체가 생성되거나 파괴될 때의 이벤트를 나타냅니다. 생성은 생명선이 시작되는 지점에, 파괴는 생명선이 끝나는 지점에 표시됩니다.


처리 흐름도는 다음과 같은 상황에서 유용하게 사용됩니다:

- 시스템의 특정 시나리오나 유스케이스를 통해 객체 간의 상호작용을 이해하고자 할 때
- 시스템의 동작을 설계하거나 문서화할 때
- 시스템의 동작을 분석하거나 디버깅할 때
- 시스템의 요구사항을 명확히 하고자 할 때

처리 흐름도는 복잡한 시스템의 동작을 단순화하여 표현할 수 있으며, 개발자와 이해관계자 간의 커뮤니케이션을 돕는 시각적 도구로서 중요한 역할을 합니다.

소프트웨어 처리 흐름도는 소프트웨어 처리 관점에서 특정 요청이 어떠한 처리 순서로 어떤 소프트웨어 객체와 어떻게 상호작용을 하는 표현하기 위한 다이어그램입니다.

### 작성
- 본 문서의 정보 기술 단위는 클라이언트의 요청에 대한 처리의 주체가 되는 서비스 또는 프로그램의 유형입니다. 본 문서에서는 이를 애플리케이션 유형(application type)이라는 용어로 다루겠습니다. 다음은 애플리케이션 유형에 해당하는 대표적인 항목들입니다. 그 외 해당 요건에 일치하는 항목을 정보 기술 단위로 추가하여 주십시오.
	- 웹 서비스
	- API 서비스
	- 배치 프로그램
- 문서의 애플리케이션 유형과 업무 구분에 따라 "C 구현 > A 소프트웨어 > A 소프트웨어 처리 흐름도" 하부의 폴더를 구성하여 주십시오. 업무 구분값은 기술 문서가 해당하는 업무 영역에 의미하는 구분값을 의미합니다. 
- 문서의 위치와 이름은 다음 규칙을 적용하여 주십시오.
```
{{문서 폴더}}/C 구현/A 소프트웨어/A 소프트웨어 처리 흐름도/{{애플리케이션 유형}/{{업무 구분}}/.../{{업무 구분}}/{{문서 코드}} {{업무명}}
```

| 문서 폴더        | 애플리케이션 유형 | 업무 구분   | 서비스 코드 | 구분 번호  | 업무명 |
| ------------ | --------- | ------- | ------ | ------ | --- |
| abc/dev-docs | API 서비스   | 주문/대형제휴 | ABC    | 000001 | 주문  |
일 경우 문서의 위치는 다음과 같습니다.
```
abc/dev-docs/C 구현/A 소프트웨어/A 소프트웨어 처리 흐름도/API 서비스/주문/대형제휴/IMA-CAA-000001 주문
```

1. 문서 정보
	- '문서 코드' 항목은 부가적인 정보를 제외한 문서 코드 만을 기입하여 주십시오.
	- '관련문서' 항목은 해당 문서 열람 시 병행하여 비교 열람하기를 권장하는 문서의 목록입니다. [[CAA. 소프트웨어 처리 흐름도 (Software Processing Sequence Diagram)#산출물 양식|산출물 양식]]을 참고하여 기입하여 주십시오.
	- '애플리케이션 유형'은 정보 기술의 대상이 되는 서비스 또는 프로그램의 유형입니다. 
	- '업무 구분'은 업무 영역에 의미하는 구분값입니다.
	- '설명' 항목은 해당 문서의 설명을 기입하여 주십시오.
	- '태그' 항목은 특정 주제로 문서를 묶어주기 위하여 적어주는 정보입니다. [[CAA. 소프트웨어 처리 흐름도 (Software Processing Sequence Diagram)#산출물 양식|산출물 양식]]을 참고하여 기입하여 주십시오. 예를 들어 화면설계서와 ITSM 업무가 다음과 같다면

   캔버스 뷰 링크는 문서의 가독성을 높이기 위해 해당 문서를 캔버스 형태로 열람할 수 있도록 제공하는 캔버스의 링크입니다.

3. 본문
	- 적절한 소프트웨어 처리 흐름을 기술하여 줍니다.
	- 처리 흐름을 구성하는 '참여자'는 대상이 되는 애플리케이션의 소프트웨어 아키텍쳐에 기반하여 선정합니다. 예를 들어 계층형 아키텍쳐 중 MVC 모델이라면, Client/View/Controller/Model 에 해당하는 모듈이 기본적으로 참여자가 됩니다.
	- 참여자는 패키지명, 클래스명 정보를 기입하여 주십시오.
	  ![[doc/_files/Pasted image 20241202092406.png]]
	- 다른 참여자를 호출하는 메세지의 경우 "{{함수명}} {{설명}}"의 정보를 기입하여 주십시오.
	- 자신을 호출하는 메세지의 경우 "{{설명}}"을 기입하여 주십시오. 
	- 자신의 내부 함수를 호출하는 메세지의 경우 "{{내부 함수명}} {{설명}}"의 정보를 기입하여 주십시오. 내부 함수의 처리 흐름이 기술이 될 필요가 있을 경우, group 태그로 묶어 기술하여 주십시오.
	![](doc/_files/Pasted%20image%2020250605164503.png)
    - 다른 소프트웨어 처리 흐름으로 연결되는 메세지의 경우 "{{소프트웨어 처리 흐름도 문서 코드}} ({{설명}})"의 정보를 기입하여 주십시오.
	- 외부 서비스를 의존하는 메세지의 경우 "{{외부서비스 식별자}} ({{설명}})"의 정보를 기입하여 주십시오. "외부서비스 식별자"의 정보는 [[외부서비스 식별자 목록]] 문서를 참고하여 주십시오. 목록에 없는 경우 외부서비스를 식별할 수 있는 적절한 문구를 정하여 [[외부서비스 식별자 목록]] 문서에 추가하여 주십시오.
	- 처리 흐름에 대한 이해를 높이기 위해 작성자의 판단에 따라 참여자와 처리 흐름들을 추가하여 주십시오.
