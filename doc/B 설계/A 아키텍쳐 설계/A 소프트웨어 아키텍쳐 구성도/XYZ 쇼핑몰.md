| 설명    | 레이어드 아키텍처(layered architecture)는 소프트웨어를 여러 계층으로 나누어 각 계층이 특정한 역할을 수행하도록 설계하는 방식입니다. 이러한 구조는 유지보수와 확장성을 향상시키며, 각 계층은 독립적으로 개발될 수 있습니다. 다음은 각 컴포넌트에 대한 설명입니다:<br><br>1. **Presentation Layer**<br>    <br>    - **User Interfaces (UI):** 사용자와 상호작용하는 인터페이스를 말합니다. 웹 페이지, 모바일 앱 화면, 데스크톱 애플리케이션의 GUI 등이 여기에 해당합니다.<br>    - **Controllers (UIC):** 사용자의 입력을 받아 처리하고, 적절한 서비스 계층에 요청을 전달하는 역할을 합니다. MVC(Model-View-Controller) 패턴에서의 컨트롤러와 유사합니다.<br>    <br>2. **Service Layer**<br>    <br>    - **Contracts:** 서비스 계층의 인터페이스를 정의합니다. 이 계층은 외부 시스템이나 프레젠테이션 계층과의 계약을 명시합니다.<br>    - **Services:** 비즈니스 로직을 수행하지 않고, 비즈니스 계층으로부터 받은 정보를 프레젠테이션 계층에 전달하는 역할을 합니다.<br>    - **Workflow Services (WFS):** 복잡한 비즈니스 프로세스나 워크플로우를 관리합니다. 이 서비스는 여러 비즈니스 컴포넌트와 상호작용하여 작업을 조정합니다.<br>    <br>3. **Business Layer**<br>    <br>    - **Business Components (BC):** 핵심 비즈니스 로직을 구현하는 컴포넌트입니다. 이들은 비즈니스 규칙과 계산을 수행합니다.<br>    - **Workflows (WF):** 비즈니스 프로세스의 순서와 흐름을 정의합니다. 복잡한 비즈니스 로직을 여러 단계로 나누어 처리합니다.<br>    - **Activities (WFA):** 워크플로우 내의 개별적인 작업 단위를 나타냅니다. 각 활동은 특정 비즈니스 작업을 수행합니다.<br>    <br>4. **Data Layer**<br>    <br>    - **Data Access Components (DAC):** 데이터베이스나 다른 저장소로부터 데이터를 조회하거나 조작하는 로직을 포함합니다. CRUD(Create, Read, Update, Delete) 작업을 담당합니다.<br>    - **Data Agents (DA):** 외부 시스템이나 서비스로부터 데이터를 가져오거나 보내는 역할을 합니다. 데이터 소스와의 통신을 추상화합니다.<br>    <br>5. **Shared Types**<br>    <br>    - **Entities (BE):** 비즈니스 엔티티를 나타내며, 데이터베이스의 테이블에 해당하는 데이터 구조를 정의합니다.<br>    - **Enums:** 열거형 타입을 정의하여, 코드 내에서 사용되는 상수 값들을 관리합니다.<br>    <br>6. **Frameworks**<br>    <br>    - **Security:** 인증, 권한 부여, 암호화 등 보안 관련 기능을 제공합니다.<br>    - **Validation:** 입력 데이터의 유효성 검사를 수행합니다.<br>    - **Exception:** 예외 처리 로직을 관리합니다. 시스템 전반에 걸쳐 일관된 예외 처리를 가능하게 합니다.<br>    - **Logging:** 시스템의 로그를 기록하여, 오류 추적 및 모니터링을 용이하게 합니다.<br>    - **Configuration:** 애플리케이션 설정을 관리합니다. 설정 파일이나 환경 변수 등을 통해 시스템을 구성합니다.<br> |
