보편 언어(Ubiquitous Language)는 프로젝트 참여자 (기획자, 설계자, 개발자 등) 에 속하는 모두에게 공유된 언어를 뜻합니다. 이는 소프트웨어 개발 프로젝트에서 모든 이해 관계자 간에 일관된 의사소통을 촉진하고, 도메인의 복잡성을 이해하고 해결하는 데 도움이 됩니다.

표준 비즈니스 용어나 일반 전문 분야의 특정 용어의 의미와 별개로, 사용 영역은 프로젝트를 수행하는 조직 내부에서만 유효합니다.

다음의 경우에 사용합니다.

·       구성원 간 의사소통

·       설계 모델링, UML 작성 등

·       설계를 바탕으로 구현 시의 코드의 클래스명, 메소드명 정의

따라서, 보편 언어(Ubiquitous Language)는 프로젝트 개발 영역의 의도를 정확히 반영하고 핵심 개념이 잘 표현될 수 있도록 정의해야 합니다.

보편 언어(Ubiquitous Language)를 작성하는 방법은 다음과 같습니다:

1. 도메인 이해하기: 프로젝트의 핵심이 되는 도메인에 대해 깊이 이해해야 합니다. 이를 위해 도메인 전문가와 긴밀히 협력하며, 도메인에 대한 지식을 습득해야 합니다.
2. 도메인 전문가와 협력하기: 도메인 전문가와 개발자가 함께 작업하여 도메인에 대한 정확한 용어와 개념을 정의합니다. 이 과정에서 도메인 전문가의 지식과 개발자의 기술적 이해가 결합되어야 합니다.
3. 모델링: 도메인 모델을 만들면서 도메인의 주요 개념과 관계를 명확히 합니다. 이 모델은 보편 언어(Ubiquitous Language)의 기초가 됩니다.
4. 용어 정의: 도메인 모델에서 식별된 개념, 엔티티, 서비스, 이벤트 등에 대한 용어를 정의합니다. 이 용어들은 명확하고 일관되어야 하며, 도메인의 실제 용어와 일치해야 합니다.
5. 문서화: 정의된 용어와 모델을 문서화하여 모든 팀 멤버가 접근할 수 있도록 합니다. 이 문서는 프로젝트의 참조 자료로 사용됩니다.
6. 일관성 유지: 개발 과정에서 보편 언어(Ubiquitous Language)를 지속적으로 사용하고, 코드, 문서, 회의 등 모든 커뮤니케이션에서 일관성을 유지합니다.
7. 반복적인 검토와 개선: 프로젝트가 진행됨에 따라 도메인에 대한 이해가 깊어지고, 새로운 요구사항이 나타날 수 있습니다. 이에 따라 보편 언어(Ubiquitous Language)도 지속적으로 검토하고 필요에 따라 개선합니다.
<br>

```
"도메인"은 특정 비즈니스, 기술, 활동 영역 또는 이해관계자들의 관심사를 의미합니다. 도메인은 소프트웨어가 해결하고자 하는 문제의 영역이며, 이는 특정 비즈니스 프로세스, 업무 규칙, 정책, 관련 데이터 및 이들 간의 상호작용을 포함합니다.
도메인 개념은 소프트웨어 설계와 개발에 있어 중심적인 역할을 합니다. 도메인 주도 설계에서는 도메인의 깊은 이해를 바탕으로 소프트웨어를 설계하고, 도메인 모델을 통해 비즈니스의 복잡성을 관리하며, 소프트웨어가 비즈니스 요구사항을 정확하게 반영하도록 합니다. 이를 통해 개발자는 비즈니스의 핵심 가치를 제공하고, 유지보수가 용이한 소프트웨어를 만들 수 있습니다.
```

### 작성

- 문서의 위치와 이름은 다음 규칙을 적용하여 주십시오.
```
{{문서 폴더}}/A 분석/A 업무 분석/B 보편 언어/{{문서 코드}} {{도메인명}}
```

| 문서 폴더        | 서비스 코드 | 구분 번호  | 도메인명 |
| ------------ | ------ | ------ | ---- |
| abc/dev-docs | ABC    | 000001 | 주문   |
일 경우 문서의 위치는 다음과 같습니다. 
```
abc/dev-docs/A 분석/A 업무 분석/B 보편 언어/IMA-AAB-000001 주문
```


1. 문서 정보
	- '문서 코드' 항목은 부가적인 정보를 제외한 문서 코드 만을 기입하여 주십시오.
	- '관련문서' 항목은 해당 문서 열람 시 병행하여 비교 열람하기를 권장하는 문서의 목록입니다. 
	- '태그' 항목은 특정 주제로 문서를 묶어주기 위하여 적어주는 정보입니다. 
<br>
2. 본문
	- '{{도메인번호}}. {{도메인}} ({{영문}}. {{약자}})' 영역의 경우 헤딩(Heading. #)을 적용하여 주십시오. 헤딩은 마크다운 헤딩(#) 태그를 의미하며, 최상위 도메인부터 부여하며 하위 도메인으로 기술이 되면서 보다 작은 단락을 의미하는 헤딩으로 태그를 기술합니다. 예를 들어 '주문' 도메인의 하위로 '선물하기' 도메인이 있는 경우 '주문' 도메인의 헤딩은 1개, '선물하기' 도메인의 경우 헤딩이 2개가 되게 됩니다. 
	- '도메인 번호'는 도메인 문단에 부여하는 숫자로 일련 번호로 부여합니다. 하위 도메인을 기술할 때 번호는 [[AAB. 보편 언어 (Ubiquitous Language)#^ea8654|산출물 양식]]에 기술되어 있는 것처럼, `상위도메인번호.하위도메인번호.`의 조합으로 부여합니다.
	- 각 도메인에 용어의 정의와 설명을 추가하며, 용어에 대해 하위 개념이 있다면 계속 표현하도록 합니다.
	- 개발 과정에서 사용되는 예약어를 피해 용어의 이름을 정의하도록 합니다.
