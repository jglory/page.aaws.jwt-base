시스템 아키텍처(System Architecture)는 시스템의 구조적 설계에 관한 개념으로, 시스템의 구성 요소들, 그들 간의 관계, 그리고 시스템의 환경과의 상호작용을 포함합니다. 시스템 아키텍처는 시스템의 기능적 요구사항과 비기능적 요구사항을 충족시키기 위해 설계되며, 시스템의 전체적인 행동과 성능을 결정짓는 중요한 역할을 합니다.

시스템 아키텍처는 일반적으로 다음과 같은 요소들을 포함합니다:

1. 구성 요소(Components): 시스템을 구성하는 개별적인 부품이나 모듈로, 특정 기능을 수행합니다. 예를 들어, 소프트웨어 시스템에서는 클래스, 패키지, 모듈 등이 구성 요소가 될 수 있습니다.
    
2. 연결(Connectors): 구성 요소들 간의 상호작용을 가능하게 하는 인터페이스나 통신 경로입니다. 이는 데이터 흐름, 메시지 전달, 함수 호출 등을 포함할 수 있습니다.
    
3. 구성(Configuration): 구성 요소들과 연결들이 어떻게 조합되어 전체 시스템을 이루는지에 대한 설계입니다. 이는 시스템의 토폴로지와 구조를 정의합니다.
    
4. 제약 조건(Constraints): 시스템 설계에 영향을 미치는 기술적, 비즈니스적, 법적, 운영적 제약 조건들입니다.
    
5. 정책(Policies): 시스템의 운영과 관리를 위한 규칙이나 지침입니다.
    

시스템 아키텍처는 시스템의 설계 초기 단계에서 중요한 역할을 하며, 시스템의 성공적인 구현과 유지보수에 필수적입니다.

### 작성

- 문서의 위치와 이름은 다음 규칙을 적용하여 주십시오.
```
{{문서 폴더}}/A 분석/B 아키텍쳐 분석/B 현행 시스템 아키텍쳐 구성도/{{문서 코드}}
```

| 문서 폴더        | 서비스 코드 | 구분 번호  |
| ------------ | ------ | ------ |
| abc/dev-docs | ABC    | 000001 |
일 경우 문서의 위치는 다음과 같습니다. 
```
abc/dev-docs/A 분석/B 아키텍쳐 분석/B 현행 시스템 아키텍쳐 구성도/IMA-ABB-000001
```
<br>

1. 문서 정보
	- '문서 코드' 항목은 부가적인 정보를 제외한 문서 코드 만을 기입하여 주십시오.
	- '관련문서' 항목은 해당 문서 열람 시 병행하여 비교 열람하기를 권장하는 문서의 목록입니다. [[ABB. 현행 시스템 아키텍쳐 구성도 (Current System Architecture Diagram)#산출물 양식|산출물 양식]]을 참고하여 기입하여 주십시오.
	- '설명' 항목은 해당 문서의 설명을 기입하여 주십시오.
	- '태그' 항목은 특정 주제로 문서를 묶어주기 위하여 적어주는 정보입니다. [[ABB. 현행 시스템 아키텍쳐 구성도 (Current System Architecture Diagram)#산출물 양식|산출물 양식]]을 참고하여 기입하여 주십시오.
<br>
2. 캔버스 뷰 링크
	캔버스 뷰 링크는 문서의 가독성을 높이기 위해 해당 문서를 캔버스 형태로 열람할 수 있도록 제공하는 캔버스의 링크입니다.
