테이블 관계도(Table Relationship Diagram)는 데이터베이스 내의 테이블들 간의 관계를 시각적으로 표현한 다이어그램입니다. 이 다이어그램은 데이터베이스 설계자나 개발자가 데이터베이스의 구조를 이해하고, 데이터 간의 관계를 명확히 하며, 데이터베이스의 무결성을 유지하는 데 도움을 줍니다.

테이블 관계도는 주로 다음과 같은 관계를 나타냅니다:

1. 일대일(One-to-One) 관계: 두 테이블 간에 1:1 관계가 있을 때, 한 테이블의 각 레코드가 다른 테이블의 단 하나의 레코드와만 연결됩니다. 예를 들어, 사람 테이블과 여권 테이블이 일대일 관계를 가질 수 있습니다.
    
2. 일대다(One-to-Many) 관계: 한 테이블의 레코드가 다른 테이블의 여러 레코드와 연결될 수 있습니다. 예를 들어, 한 명의 고객이 여러 개의 주문을 할 수 있는 경우, 고객 테이블과 주문 테이블 사이에 일대다 관계가 있습니다.
    
3. 다대다(Many-to-Many) 관계: 두 테이블의 레코드들이 서로 다수의 레코드와 연결될 수 있습니다. 이러한 관계는 일반적으로 중간 테이블(연결 테이블 또는 조인 테이블이라고도 함)을 사용하여 구현됩니다. 예를 들어, 학생들과 수업 간의 관계는 다대다일 수 있으며, 학생-수업 연결 테이블을 통해 관리됩니다.
    

테이블 관계도를 만들 때, 다음과 같은 기호를 사용하여 관계의 유형을 나타냅니다:

- 직선: 두 테이블 간의 관계를 나타냅니다.
- 까마귀 발(Crow's foot): 일대다 관계에서 '다' 쪽의 끝에 위치하는 기호로, 여러 레코드를 나타냅니다.
- 선의 끝에 작은 원: 일대일 관계를 나타냅니다.
- 선의 끝에 수직선: 관계의 필수적인 측면을 나타냅니다. 예를 들어, 한 테이블의 레코드가 반드시 다른 테이블의 레코드와 연결되어야 할 때 사용합니다.

테이블 관계도는 데이터베이스 관리 시스템(DBMS)의 설계 도구나 다이어그램 소프트웨어를 사용하여 만들 수 있으며, 데이터베이스의 논리적 구조를 표현하는 데 중요한 역할을 합니다.

### 작성
- 본 문서는 업무 영역을 정하고 업무 영역을 기준으로 관련된 테이블 간의 관계도를 작성합니다.
- 문서의 위치와 이름은 다음 규칙을 적용하여 주십시오.
```
{{문서 폴더}}/A 분석/B 아키텍쳐 분석/C 현행 테이블 관계도/{{문서 코드}} {{업무영역명}}
```

| 문서 폴더        | 서비스 코드 | 구분 번호  | 업무영역명 |
| ------------ | ------ | ------ | ----- |
| abc/dev-docs | ABC    | 000001 | 주문    |
일 경우 문서의 위치는 다음과 같습니다. 
```
abc/dev-docs/A 분석/B 아키텍쳐 분석/C 현행 테이블 관계도/IMA-ABC-000001 주문
```
<br>
1. 문서 정보
	- '문서 코드' 항목은 부가적인 정보를 제외한 문서 코드 만을 기입하여 주십시오.
	- '데이터베이스' 항목은 기술하고자 하는 업무 영역이 속한 데이터베이스 인스턴스 명을 기입하여 주십시오.
	- '관련문서' 항목은 해당 문서 열람 시 병행하여 비교 열람하기를 권장하는 문서의 목록입니다. [[ABC. 현행 테이블 관계도 (Current Table Relationship Diagram)#산출물 양식|산출물 양식]]을 참고하여 기입하여 주십시오.
	- '설명' 항목은 해당 문서의 설명을 기입하여 주십시오.
	- '태그' 항목은 특정 주제로 문서를 묶어주기 위하여 적어주는 정보입니다. [[ABC. 현행 테이블 관계도 (Current Table Relationship Diagram)#산출물 양식|산출물 양식]]을 참고하여 기입하여 주십시오.
<br>
2. 캔버스 뷰 링크
	캔버스 뷰 링크는 문서의 가독성을 높이기 위해 해당 문서를 캔버스 형태로 열람할 수 있도록 제공하는 캔버스의 링크입니다.
<br>
3. 본문
	- 중심 엔티티(main entity) 역할을 하는 주 테이블을 선정합니다. 주 테이블을 기준으로 관련 테이블을 가능한 한도 내에서 Top-Down 방식으로 표현 합니다.
	- 테이블의 모든 컬럼과 관계를 표기하지 않습니다. 시스템 처리 과정에서 명시적으로 관계가 이루어지는 컬럼과 관계를 표기합니다.
	- 이외의 상세 정보는 산출물 중 테이블 정의서를 통해 습득합니다.

	- 주 테이블을 lightblue 색상으로 표시해 줍니다. 
	- 주키(Primary Key)는 왼쪽에 공모양의 아이콘을 통해 표현합니다.
	- 외래키(Foreign Key)는 관계선 위에 표현 해 줍니다. 물리적인 외래키를 성능, 관리 등의 이슈로 정의하지 않고 논리적인 관계만 가져가는 경우도 표현해 주십시오.



```
전통적인 관계도에 표현되는 모든 정보를 표기하지 않는 이유는 많은 정보의 제공이 관계도의 목적이 되는 정보 전달 요소인 관계성 정보가 흐려짐을 방지하고, 다른 정보를 제공하는 다른 문서들을 통해 다면적인 정보를 제공함으로 모델링의 의도를 입체적으로 파악하도록 하기 위함입니다.
```
