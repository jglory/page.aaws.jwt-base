시퀀스 다이어그램 (Sequence Diagram)은 UML (Unified Modeling Language)에서 사용되는 다이어그램 중 하나로, 시스템에서 객체들 간의 상호작용과 메시지 흐름을 시간 순서에 따라 시각화하는 데 사용됩니다. 주로 시스템 설계 및 분석 단계에서 활용되며, 복잡한 프로세스나 상호작용을 명확히 표현하는 데 유용합니다.
<br><br>
```plantuml


' 참여자들
participant "User" as User
participant "Admin" as Admin
box "middleware\n" #LightBlue
participant "UserPermissionManager" as UserPermissionManager
end box
participant "UserController" as UserController
participant "Kernel" as Kernel
participant "UserCache" as UserCache
participant "UserRepository" as UserRepository


==User Requests==
User -> UserPermissionManager: user request
activate User
activate UserPermissionManager
UserPermissionManager -> UserCache: find user cache
activate UserCache
UserCache -> UserCache: find user cache
alt user cache not found!
    UserCache -> UserRepository: query user permission
    activate UserRepository
    UserCache <-- UserRepository: user permission
    deactivate UserRepository
    UserCache -> UserCache: cache user permission
end
UserPermissionManager <-- UserCache: user permission
deactivate UserCache
UserPermissionManager -> UserPermissionManager: check permissions
alt user has permission that is required to access
    UserPermissionManager -> UserController: user request
    activate UserController
    UserPermissionManager <-- UserController: 200 ok
    deactivate UserController
    User <-- UserPermissionManager: 200 ok
else
    User <-- UserPermissionManager: \n\n403 error - access not granted!
end
deactivate UserPermissionManager
deactivate User



==Login==
User ->  UserController: login
activate User
activate UserController
UserController -> UserController: fire LoginEvent
User <-- UserController: ok
deactivate UserController
deactivate User

Kernel -> UserCache: receive
activate Kernel
activate UserCache
UserCache -> UserCache: cache user permission
Kernel <- UserCache
deactivate UserCache
deactivate Kernel



==Logout==
User ->  UserController: logout
activate User
activate UserController
UserController -> UserController: fire LogoutEvent
User <-- UserController: ok
deactivate UserController
deactivate User

Kernel -> UserCache: receive
activate Kernel
activate UserCache
UserCache -> UserCache: flush user permission
Kernel <- UserCache
deactivate UserCache
deactivate Kernel



==Permission Has Changed !==
Admin -> UserPermissionManager: change permission
activate Admin
activate UserPermissionManager
UserPermissionManager -> UserController: change permission
activate UserController
UserController -> UserController: fire PermissionHasChangedEvent
UserPermissionManager <-- UserController: ok
deactivate UserController
Admin <-- UserPermissionManager: ok
deactivate UserPermissionManager
deactivate Admin

Kernel -> UserCache: receive
activate Kernel
activate UserCache
UserCache -> UserCache: remove user permission cache
Kernel <- UserCache
deactivate UserCache
deactivate Kernel

```

처리 흐름도(Sequence Diagram)은 [UML(Unified Modeling Language)](https://en.wikipedia.org/wiki/Unified_Modeling_Language)의 일부로, 객체 간의 상호작용을 시간 순서에 따라 표현하는 다이어그램입니다. 처리 흐름도는 특히 시스템의 동작을 이해하고, 시스템 내에서 메시지가 어떻게 흐르는지를 시각화하는 데 유용합니다.
<br>
<br>
## 구성 요소
<br>

##### 객체 (Object)
시스템의 행위자 혹은 시스템 내의 유효한 객체를 처리를 하는 주체. 다이어그램 상단에 수평으로 배치되며, 생명선(Lifeline)을 가진다.

![[_files/68b96c6cd9a1e24e87cb7497d4caa847_MD5.jpeg]]
<br>
<br>

##### 생명선 (Operation)

각 객체 아래로 길게 뻗어 내려가는 수직선으로, 객체의 생명 주기를 나타냅니다. 객체가 시스템 내에서 활동하는 기간 동안 생명선이 계속 됩니다.

![[_files/68b96c6cd9a1e24e87cb7497d4caa847_MD5.jpeg]]
<br>
<br>

##### 활성화 바 (Activation Bar)
객체가 작업을 수행하고 있음을 나타내는 두꺼운 수직선으로, 생명선 위에 그려집니다. 활성화 바의 길이는 해당 작업의 지속 시간을 나타냅니다.

![[_files/3b7e23fea9fe7b342cf1d98bc617f6a8_MD5.jpg]]

<br>
<br>

##### 메시지 (Message)
객체 간의 상호작용을 나타내는 화살표로, 메시지를 보내는 객체에서 받는 객체로 향합니다.


| 유형                                | 의미                                                                         |
| --------------------------------- | -------------------------------------------------------------------------- |
| 동기 메시지<br>(Synchronous message)   | 메시지 전송 객체가 요청을 보낸 후 결과 메시지의 응답을 기다림. 프로그램 내 일반적인 함수 호출과 동일한 동작 방식의 시지를 표현 |
| 비동기 메시지<br>(Asynchronous message) | 메시지 전송 객체가 요청을 보낸 후 결과 메시지의 응답을 기다리지 않음. 보통 개별 쓰레드 간의 통신 및 새 쓰레드의 생성 등에 사용 |
| 자체 메시지<br>(Self message)          | 자체적으로 작업을 처리 할 때 자신에게 보내는 메시지                                              |
| 반환 메시지<br>(Return Message)        | 요청에 대한 결과 메시지                                                              |

##### 흐름 제어 (Flow Control)

처리 로직에는 if, for, while 과 같은 흐름을 제어하는 표현식이 있는데 이것을 표현하는 요소들입니다. 

- Guard
단일 메시지에 대한 조건을 명시하는 방법

![[_files/71d119ed11eba43475278679cc9b5ad1_MD5.jpeg]]

- Sequence Fragment
범위로 조건을 명시하는 방법. 특정 부분에 대해 조건을 명시할 때 사용

&nbsp;&nbsp;&nbsp; - alternative
alt 로 줄여 사용. 조건문 if/else 문을 표현

![[_files/5afc4422f6a3933b3f01aba5cbd0f183_MD5.jpeg]]

&nbsp;&nbsp;&nbsp; - option
opt 로 줄여 사용. 조건문 if 문을 표현

![[_files/40015467d73052e1b0e4cddd4101ce38_MD5.jpeg]]
&nbsp;&nbsp;&nbsp; - loop
반복문 for,while 등의 구문을 표현

![[_files/de94fd23e81e53610740e36385b8ed6e_MD5.jpeg]]
