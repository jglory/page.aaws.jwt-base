클래스 다이어그램 (Class Diagram)은 UML (Unified Modeling Language)에서 사용되는 구조적 다이어그램으로, 시스템의 클래스, 속성, 메서드 및 클래스 간의 관계를 시각적으로 표현하는 데 사용됩니다. 소프트웨어 설계에서 객체 지향 시스템의 정적 구조를 정의하고 분석하는 데 매우 유용합니다.

<br><br>
```plantuml
skinparam linetype ortho

class UserCredentialDto {
    - email: String
    - password: String

    + getEmail(): String
    + setEmail(String): void
    + getPassword(): String
    + setPassword(String): String
}

class UserDto {
    - id: Long

    + getId(): Long
    + setId(Long): void
}

class UserController {
    - userService: UserService 
    + login(UserDto, HttpServletResponse): ResponseEntity<Object>
}

interface UserService {
    + getUserByUserLoginCredential(UserCredentialDto): UserDto
    + verifyUserLoginCredential(UserCredentialDto): boolean 
}

class UserServiceImpl implements UserService {
    - userRepository: UserRepository
}

interface UserRepository {
    + findUserByUserLoginCredential(UserCredentialDto): UserDto
}

class UserRepositoryImpl implements UserRepository {

}

UserCredentialDto <|-- UserDto
UserServiceImpl "1" --o "1" UserController
UserRepositoryImpl "1" --o "1"  UserService
UserCredentialDto ...>  UserService
UserCredentialDto ..>  UserRepository
UserDto ..> UserRepository
UserDto ..> UserController
```
<br>
<br>


클래스 구조도(Class Structure Diagram)은 객체 지향 시스템의 정적 구조를 모델링 하는 [UML(Unified Modeling Language)](https://en.wikipedia.org/wiki/Unified_Modeling_Language) 다이어그램의 한 유형입니다. 클래스 다이어그램은 시스템 내의 클래스들 간의 관계를 시각적으로 표현하며, 클래스의 속성(attributes), 메서드(operations), 그리고 클래스 간의 관계를 나타냅니다.
<br>
<br>
## 구성 요소

<br>

##### 속성 (Attribute)
```
visibility name: attribute type [multiplicity] = default value
접근제어자 이름: 속성 타입 [배열 개수] = 기본값
```

```plantuml
class A {
    - value1: String = "private"
    # value2: String = "protected"
    + value3: String = "public"
    ~ value4: String = "package private"
}

```

<br>
<br>

##### 행동 (Operation)
```
visibility name (parameter list): type of value returned
접근제어자 이름 (매개 변수 혹은 인자 리스트): 반환 타입
```

```plantuml
class A {
    - method1(Long, String): String
    # method2(Long, String): String
    + method3(Long, String): String
    ~ method4(Long, String): String
}

```
<br>
<br>

##### 참고
- Stereo type: <<>> 으로 표기. 보통 UML 문법으로 나타낼 수 없는 추가 의미나 목적을 표기
```plantuml
interface A <<metaclass>> {}
```
- Static(정적) 속성/행동 일 경우 밑줄을 그어 표기
```plantuml
class A {
    - {static} value1: String = "private"
    + {static} method1(Long, String): String
}
```

## 클래스 관계

##### 의존 (Dependency)

클래스가 다른 클래스와의 의존성을 가지고 있는 경우. 의존 클래스의 상태 변화는 이를 참조하고 있는 클래스의 상태 변화(의존)를 의미한다.

표기방법 - 점선 + 화살표
```plantuml
class UserLoginCredentialDto {
    - email: String
    - password: String

    + getEmail(): String
    + setEmail(String): void
    + getPassword(): String
    + setPassword(String): String
}

interface UserRepository {
    + findUserByUserLoginCredential(UserLoginCredentialDto): UserDto
}

UserRepository <. UserLoginCredentialDto
```

<br>
<br>

##### 연관 (Association)

클래스가 다른 클래스와의 연관성을 가지고 있는 경우. 보통 클래스의 인스턴스가 다른 클래스의 인스턴스를 변수로 참조를 가지고 있을 경우를 의미한다.

표기방법 - 실선 + 화살표
```plantuml
class UserController {
    - userService: UserService 
    + login(UserDto, HttpServletResponse): ResponseEntity<Object>
}

class UserServiceImpl {
    - userRepository: UserRepository
}

class UserRepositoryImpl {

}


UserServiceImpl "1" -o "1" UserController
UserRepositoryImpl "1" -o "1"  UserServiceImpl
```

<br>
<br>

##### 집합연관 (Aggregation)
연관(Association) 개념을 확장한 것으로 전체와 부분의 관계를 나타낸다. 두 개의 클래스가 서로 연관 관계를 가지며 전체 - 부분 관계를 가질 때 집한연관(Aggregation)으로 표기한다. 집합연관의 중요한 점은 부분이 되는 클래스의 라이프 사이클은 전체가 되는 클래스의 라이프 사이클과 서로 관련성이 없다는 점이다.

표기방법 - 실선 + 속이 빈 마름모
```plantuml
class UserController {
    - userService: UserService 
    + UserController(UserService)
    + login(UserDto, HttpServletResponse): ResponseEntity<Object>
}

class UserServiceImpl {
    - userRepository: UserRepository
    + UserService(UserRepository)
}

class UserRepositoryImpl {

}


UserServiceImpl "1" -o "1" UserController
UserRepositoryImpl "1" -o "1"  UserServiceImpl
```


<br>
<br>


##### 합성연관 (Composition)
집합연관(Aggregation)처럼 전체와 부분의 관계를 가지고 있지만 부분에 해당하는 클래스의 라이프 사이클이 전체를 의미하는 클래스의 라이프 사이클과 동일하다는 점에서 차이점을 보인다. (전체에 해당하는 클래스 소멸 시 부분 클래스도 함께 소멸)

표기방법 - 실선 + 속이 찬 마름모
```plantuml
class UserController {
    - userService: UserService 
    + UserController()
    + login(UserDto, HttpServletResponse): ResponseEntity<Object>
}

class UserServiceImpl {
    - userRepository: UserRepository
    + UserService()
}

class UserRepositoryImpl {

}


UserServiceImpl "1" -* "1" UserController
UserRepositoryImpl "1" -* "1"  UserServiceImpl
```
