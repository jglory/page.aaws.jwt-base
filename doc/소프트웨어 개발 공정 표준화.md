
## 1. 목적

소프트웨어 개발 공정 표준화는 롯데홈쇼핑(이하 자사)에서 소프트웨어를 개발하기 위한 일련의 절차와 원칙들의 체계적인 집합을 말합니다. 본 문서는 자사에서 소프트웨어를 개발하기 위한 절차와 수단과 적용에 대한 가이드를 제시합니다. 개발 공정의 표준화는 팀이 효과적으로 협력하고 프로젝트를 계획, 설계, 구현, 테스트, 유지보수하는 데 도움을 주며, 소프트웨어 개발 프로세스의 생명 주기 관리를 용이하게 합니다. 


```
소프트웨어 개발 프로세스 생명주기(Software Development Life Cycle, SDLC)는 소프트웨어를 개발하는 과정을 체계적으로 관리하기 위한 프로세스입니다. SDLC는 소프트웨어의 기획부터 유지보수 및 폐기에 이르기까지의 전체적인 흐름을 정의하며, 프로젝트의 진행 상황을 예측 가능하게 만들고 위험을 관리하는 데 도움을 줍니다.

SDLC는 일반적으로 다음과 같은 단계로 구성됩니다:

1. 요구사항 분석(Requirement Analysis): 이 단계에서는 사용자의 요구사항을 수집하고 분석하여 소프트웨어가 해결해야 할 문제를 명확히 합니다.
    
2. 시스템 설계(System Design): 요구사항을 바탕으로 시스템의 아키텍처를 설계합니다. 이 단계에서는 데이터 모델, 아키텍처 다이어그램, 인터페이스 설계 등이 이루어집니다.
    
3. 구현(Implementation): 설계된 시스템을 기반으로 실제 코드를 작성합니다. 개발자들은 이 단계에서 소프트웨어의 기능을 구현합니다.
    
4. 테스트(Testing): 작성된 코드가 요구사항을 만족하는지 검증하기 위해 다양한 테스트를 수행합니다. 버그를 찾아내고 수정하는 과정을 포함합니다.
    
5. 배포(Deployment): 테스트를 통과한 소프트웨어를 사용자 환경에 배포합니다. 때로는 여러 단계에 걸쳐 점진적으로 배포하는 경우도 있습니다.
    
6. 유지보수(Maintenance): 소프트웨어가 실제 운영 환경에서 사용되는 동안 발생하는 문제를 수정하고, 필요에 따라 기능을 추가하거나 개선하는 작업을 수행합니다.
```



## 2. 적용 대상 및 범위

- 개발 사업 수행 시 개발 및 구현을 담당하는 조직, 부서, 또는 협력업체



## 3. 특징

- [도메인 주도 설계(DDD. Domain Driven Design)](https://en.wikipedia.org/wiki/Domain-driven_design) 방법을 지향합니다.
- [마이크로 서비스 아키텍쳐(MSA. Micro Service Architecture)](https://en.wikipedia.org/wiki/Microservices) 설계를 지원합니다.
- 개발 단계 중 개발 및 구현에 관련된 분석, 설계, 구현, 시험 단계를 포함하고 전개, 인도 과정을 제외하였습니다.


```
도메인 주도 설계(DDD. Domain Driven Design)는 복잡한 소프트웨어 시스템을 설계할 때, 도메인의 복잡성을 관리하고, 비즈니스 요구사항을 정확하게 반영하는 데 유용한 방법론입니다. DDD를 통해 개발자는 비즈니스 전문가와 긴밀히 협력하여, 비즈니스 로직을 코드에 반영하고, 유지보수가 용이하며 확장 가능한 소프트웨어를 만들 수 있습니다.

도메인(Domain)은 특정한 주제나 관심 영역을 나타내는 개념입니다. 소프트웨어 개발에서 도메인은 해당 소프트웨어 시스템이나 애플리케이션이 다루는 문제 영역 또는 비즈니스 영역을 가리킵니다. 간단하게 말하면, 도메인은 특정한 지식이나 활동들의 집합체로 생각할 수 있습니다.
도메인에는 다양한 개념, 규칙, 프로세스, 그리고 관련된 업무들이 포함되어 있습니다. 이 도메인 지식은 소프트웨어를 설계하고 개발하는 데 중요한 역할을 합니다. 이러한 도메인 지식을 잘 이해하고 활용하는 것이 소프트웨어가 비즈니스 요구사항을 충족시키고 유지보수 가능하며 효과적으로 발전할 수 있는 핵심입니다.

마이크로서비스 아키텍처(Microservices Architecture, MSA)는 소프트웨어를 작고 독립적으로 배포 가능한 서비스의 집합으로 구성하는 설계 접근 방식입니다. 이러한 서비스들은 각각의 비즈니스 기능을 수행하며, 서로 네트워크를 통해 통신합니다. 마이크로서비스 아키텍처는 대규모, 복잡한 애플리케이션을 더 관리하기 쉽고, 확장 가능하며, 유연한 방식으로 개발할 수 있도록 돕습니다.
```


## 4. 구조

단계, 활동, 작업의 3개 계층으로 구성되어 있습니다. 

![[doc/_files/개발방법론 구조 2.png]]

- 단계 : 개발방법론의 생명주기
- 활동 : 단계를 세분화한 작업 그룹
- 작업 : 실제 작업이 행해지는 업무의 최소 단위
- 산출물 : 각 작업에서 도출되는 결과물



## 5. 코드 체계

각 개발 단계에 따른 산출물 또는 산출물의 항목 중 정보로서 유효한 의미를 가지는 단위마다 코드를 부여합니다. 이는 자료를 구별하고, 동질의 그룹으로 분류하고 간결한 표현과 관계성을 표현하기 위함입니다. 

###### 코드 체계

```
	{{서비스코드}}-{{단계코드}}{{활동코드}}{{산출물코드}}-{{구분번호}}
```


| 코드 체계   | 설명                                                  |
| ------- | --------------------------------------------------- |
| 서비스  코드 | 사업 또는 서비스에 부여한 3자리 코드. [[서비스코드 목록\|서비스코드 목록]] 문서 참조 |
